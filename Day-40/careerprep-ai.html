How this was built

System Prompt Design

The underlying Claude call is scoped to a single job: act as an ATS-aware resume and interview-readiness coach for students/early-career job seekers. It's instructed to always return a strict JSON schema (score, verdict, sections of feedback, recommendations with reasoning) so the UI can render deterministically instead of parsing free-form prose. Edge cases are explicitly handled: if pasted text isn't resume-like, it returns a clarification_needed flag instead of guessing; if no job description is given, it scores against general ATS best practices and says so; abusive or off-topic input is redirected back to resume coaching without lecturing the user.

Why the UI Fits

Instead of a generic chat box, the interface leads with a circular score dial (the single number students care about most), followed by a structured report with distinct sections for strengths, risks, and keyword gaps — mirroring how a career counselor would annotate a resume. A lightweight follow-up chat sits underneath for open questions ("how do I phrase this bullet better?") without forcing the whole session into raw chat.

Extending This

  • Add a PDF/DOCX parser (e.g. pdf.js) so uploads aren't limited to .txt.
  • Add memory across sessions by storing prior analyses and diffing score improvement over time.
  • Add a "mock interview" tool-call step where Claude generates role-specific questions and evaluates spoken/typed answers turn by turn.
  • Add an MCP connector to job boards (e.g. Indeed) to auto-pull a real JD instead of pasting one.
