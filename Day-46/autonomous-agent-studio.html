13 · Architecture Overview

    

      
PLANNER
Planner
Reads the raw source, forms a review plan: what to check for bugs, security holes, performance bottlenecks, style/maintainability issues, and missing documentation.

      
EXECUTOR
Executor
Produces the first working draft: fixes obvious bugs, patches security issues, and adds baseline documentation, following the Planner's plan.

      
EVALUATOR
Evaluator
Scores the current draft every round across correctness, performance, maintainability, security, and documentation — returns strict JSON, called fresh each round with the current draft.

      
CRITIC
Critic
Given the Evaluator's scores, writes a concrete, prioritized critique of what's still wrong and why, which becomes the Improver's brief.

      
IMPROVER
Improver
Takes the prior draft + evaluation + critique and rewrites the code to resolve the flagged issues — its output is what gets re-evaluated next round.

      
MEMORY
Memory Manager
After each round, condenses what changed and what recurring issues persist into a running memory log, so later rounds don't repeat solved problems.

      
SAFETY
Safety Monitor
Independently checks each new draft for newly introduced security regressions or destructive changes before the round is accepted.

      
REVIEWER
Final Reviewer
Runs once, after a stop condition fires — polishes the final draft and writes the human-readable closing summary naming the exact stop reason.

    

    

      Information flow between rounds is entirely governed by the stop-check: as long as no condition fires, the Evaluator's JSON and the Critic's prose are handed to the Improver, whose output becomes next round's input to the Evaluator — a genuine cycle, not a fixed pipeline. The stop-check is evaluated after Evaluator + Safety Monitor + Critic + Memory Manager run, in the fixed priority order threshold → plateau → hard cap, and only its outcome decides whether another Improver call happens or control branches to the Final Reviewer.
    

  


  

    
14 · Extension Ideas

    
    
      
  • Add a Test Generator agent that writes unit tests for the current draft each round, and feed failing-test output into the Critic as additional evidence.
    • 
      
  • Add a Static Analysis tool-use step (real linter/AST parse) whose output is injected into the Evaluator's prompt for grounding, rather than relying purely on model judgement.
    • 
      
  • Persist history across sessions so the Memory Manager can recall recurring anti-patterns from previous pipeline runs on the same codebase.
    • 
      
  • Let the Safety Monitor have veto power: if it flags a critical regression, force an extra Improver pass regardless of the Evaluator's score that round.
    • 
      
  • Parallelize independent dimensions (security vs performance) as separate agent calls per round, then merge into one composite score.
    • 
      
  • Add a human-in-the-loop approval gate between the plateau stop and the Final Reviewer for high-stakes codebases.
